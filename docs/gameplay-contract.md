# 카멜론 게임성 계약서

상태: Phase 0 기준선

이 문서는 기능 목록이 아니라, 다음 리빌드에서 게임성·맵·AI·네트워크가 같은 기준으로 움직이게 하기 위한 계약서다. 원작의 핵심 재미는 참고하되 원작의 코드·리소스·미확인 규칙을 복제하지 않는다.

## 1. 제품 목표

카멜론은 최대 8인이 짧은 라운드를 반복하는 실시간 숨바꼭질 게임이다.

- 카멜레온은 배경을 관찰하고, 색·패턴·자세를 조정하고, 술래의 판단을 속인다.
- 술래는 이동·시야·소리·색 차이·실루엣을 조합해 의심 대상을 좁힌다.
- 한 라운드 안에 이동 위험, 위장 준비, 정지 판단, 발견 긴장감이 모두 존재해야 한다.
- 온라인 1개 통합 로비와 최대 8인은 웹 서비스 운영 정책이다.
- 감염 모드·AI 고정 역할·탄약 제한은 기본 모드가 아닌 선택 모드다.

## 2. 재미 검증 질문

각 라운드가 아래 질문에 “예”라고 답할 수 있어야 한다.

1. 카멜레온이 숨을 장소를 고르는 과정에 위험과 선택이 있는가?
2. 단색으로 칠하는 것보다 위치·자세·실루엣을 맞추는 것이 유리한가?
3. 술래가 발견 직전에 얻는 시각·소리 단서가 이해 가능한가?
4. 술래가 틀리게 판단하거나 총을 낭비할 위험이 있는가?
5. 라운드가 끝난 뒤 “저기에 숨어 있었구나”라는 회고가 생기는가?
6. AI도 순간이동이나 고정값이 아니라 같은 규칙으로 플레이하는가?

## 3. 기본 라운드 계약

```text
lobby -> prepare -> hide -> hunt -> reveal -> result -> lobby
```

- `lobby`: 참가·준비·맵·규칙 설정
- `prepare`: 술래는 수색 영역에 들어가지 않음
- `hide`: 카멜레온이 직접 이동해 표면을 샘플링하고 칠함
- `hunt`: 술래가 이동·관찰·추리·태그 수행
- `reveal`: 모든 위치와 위장 결과 공개
- `result`: 승패·개인 성과·다음 라운드 준비

최소 2인이 모이지 않은 라운드는 시작하지 않는다. 8인 라운드의 기본 역할은 1 술래와 7 카멜레온으로 시작하고, 실제 플레이테스트 결과에 따라 2 술래 옵션을 별도로 조정한다.

## 4. 맵 계약

초기 8인 맵의 목표값은 고정 법칙이 아니라 플레이테스트용 KPI다.

- 3개 핵심 구역
- 2개 이상의 순환 루트
- 중앙의 빠르지만 위험한 경로와 외곽의 느리지만 안전한 경로
- 주요 은신처 8~12개
- 보조 장애물 16~24개
- 20~30%의 열린 이동 공간
- 모든 스폰에서 직접 보이는 주요 은신처 금지
- 2명이 동시에 통과할 수 없는 불필요한 병목 금지
- 가장 먼 구역 접근 6~10초
- 전체 순환 이동 25~35초

맵 오브젝트는 단순한 박스가 아니라 다음 정보를 가져야 한다.

```text
propId
visualModel
collisionShape
paintableSurfaces
silhouetteProfile
coverHeight
coverQuality
navigationCost
spawnAllowed
hideAllowed
```

## 5. 시스템 경계

- `round`: 페이즈·역할·승패만 처리
- `commands`: 이동·페인트·문·발사·도발을 검증 가능한 명령으로 처리
- `simulation`: 권위 있는 상태 변화와 시간 진행
- `world`: Three.js 렌더링·충돌·카메라
- `ai`: 네비게이션·인지·행동 선택
- `maps`: 시각 모델과 충돌·은신·네비게이션 데이터를 함께 제공
- `session`: 온라인 전송과 재접속만 담당
- `GameView`: 화면 조립과 입력 연결만 담당

UI에서 방 상태를 직접 통째로 덮어쓰지 않는다. 게임 상태는 명령을 통해서만 변경하며, 최종적으로 권위 있는 호스트 또는 게임 서버가 검증한다.

## 6. 출시 전 필수 검증

- 2·4·8인 역할 배정과 승패
- 재접속·퇴장·관전자 전환
- 중복 발사와 탄약 차감
- 모든 스폰의 충돌·경계·공정성
- AI의 실제 이동·탐색·은신
- MacBook 키보드·마우스
- iPhone Safari와 Android Chrome 가로 터치
- 데스크톱 60 FPS 목표, 모바일 30 FPS 하한
- 채팅 도배·금칙어·긴 텍스트 처리
- 맵별 생존 시간·발견률·이동 경로·승률

## 7. 페이즈 완료 규칙

각 페이즈는 코드가 동작하는 것만으로 완료하지 않는다.

1. 로컬 검증과 브라우저 시나리오를 실행한다.
2. 데스크톱과 모바일 입력을 확인한다.
3. 변경 파일·잔여 위험·다음 페이즈를 기록한다.
4. 커밋과 푸시 후 결과를 보고한다.
